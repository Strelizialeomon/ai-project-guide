# 四层模型

`AGENTS.md` 第二节的展开。拿不准该上哪几层时读这份。

## 四层各是什么

### 界面（前端）

**用户看得见、点得到的那层。** 页面、按钮、表格、表单。

- **少了会怎样**：没有能用的东西，无从谈起。
- **单独存在够不够**：够——如果它不需要记住任何东西、不需要别人访问、不需要存文件。见 `案例-正例与反例.md` 的反例。

### 后端

**在服务器上跑的逻辑。** 算数、判权限、连外部系统、按条件筛数据。

- **少了会怎样**：所有逻辑都得在用户自己的浏览器里跑。轻的做不了（比如「谁还没交」要汇总所有人的数据），重的不能做（比如「不能让 A 看到 B 的」——浏览器里的东西，用户想改就能改）。
- **需要它的信号**：
  - 「不同人看到的不一样」
  - 「不能让人随便改」
  - 「要连 xx 系统 / xx 接口」
  - 要汇总、要统计、要按规则算

⚠️ **别把「界面好看」当成「逻辑做完了」。** 一个只有界面的东西，看起来能点，但背后没有任何东西在真正判断。

### 数据库

**结构化地「记住」东西。** 谁、什么时候、什么状态、什么内容。

- **少了会怎样**：东西只活在当前这个页面里。关掉、刷新、换台电脑，就没了。
- **需要它的信号**：
  - 「关掉再打开还得在」
  - 「同事也要能看到」
  - 要记录状态（交了没、批了没、到哪一步了）

⚠️ **浏览器里也能存一点东西（本机存储），但那只在他这台电脑上。** 用户说「大家都能看到」的时候，浏览器存储完全不顶用——这是最容易骗过自己的一个坑。

### 对象存储（OSS / 云存储这类）

**存大件文件。** 图片、Excel、PDF、视频。

- **少了会怎样**：文件只能放在某台机器上。量大了撑不住，而且发给别人时对方打不开（文件还在他自己电脑里）。
- **需要它的信号**：
  - 「要传图片 / Excel / 视频」
  - 「附件」「上传」「下载」
- **什么时候可以先不上**：文件很小、很少、只有他自己用，可以先跟数据放一起。但**这个「先」必须跟用户讲清楚**，不能默默这么干。

## 判据总表

从用户的话倒推，**不要从他没说的地方猜**：

| 他说了这类话 | 说明缺不了 |
|---|---|
| 「关掉再打开还得在」「同事也要能看到」 | 数据库 |
| 「不同人看到的不一样」「不能让人随便改」「要连 xx 系统」 | 后端 |
| 「要传图片 / Excel / 视频」 | 对象存储 |
| 「同事也要用」「发给大家」 | 一台大家都能访问的机器（后端 + 部署） |
| 以上都没有 | 纯工具，一层界面就够 |

**最后一问**：换个不懂行的人来用，他会不会觉得「这东西坏了」？

---

## 三个最常见的误判

### 1. 「先做个界面，让他看看效果」

界面做完，用户会以为快好了——**其实后面还有三层的活没干**。

如果你确实想先做个界面确认方向，**做完必须说清**：「这只是门面，还不能真的用，后面还差 A、B、C。」别让他拿着一个空壳去给同事看。

### 2. 「数据先存在浏览器里，以后再挪」

用户看到东西存下来了，就会当成**真的存下来了**。然后他换台电脑、清个缓存，东西没了，他会觉得「这系统坏了」。

要做就现在做对；暂时做不到，就**明说**「现在只存在你这台电脑上，换电脑就没了」。

### 3. 「附件先存本机，以后再传云上」

他自己用没问题，**一发给同事就炸**——对方点开是个打不开的路径。

只要他说过「同事也要用」，这一步就不能跳。
